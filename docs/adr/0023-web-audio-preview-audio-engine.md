# Web Audio preview audio engine

Editor-next uses a project-owned **Preview audio engine** built on Web Audio. Its source provider keeps one Mediabunny `Input` per active **Media asset** and prepares bounded, timestamp-aligned **Preview audio windows**. The engine owns playback scheduling, channel handling, **Track volume**, include/exclude, preview solo, preview mute, graph meters, and the audio-master clock. Native video remains a muted visual follower when audio monitoring owns the clock.

The full-track resource strategy is replaced by the contract proven in #108 and adopted in #109: a 2-second media-time PCM horizon, 1.5-second replenishment threshold, 50 ms pull cadence, and chunks no longer than 200 ms. Tracks prepare concurrently; initial readiness requires a playable window, metadata-proven silence, or an explicit per-track failure for every track. Scheduled `AudioBufferSourceNode` chunks share one context/media epoch. The measured continuity and node-churn gates did not require AudioWorklet. See [the accepted proof](../verification/bounded-preview-audio-window.md) and [production verification](../verification/production-preview-audio-window.md).

The provider owns decode capability checks, packet/sample timestamp alignment, caller-owned sample closure, and iterator cancellation. The controller owns generations, lookahead, stale-publication checks, and playback intent. The scheduler owns PCM and one-shot sources; the graph owns channel routing, gains, and metering. The React resource hook owns asset-level provider disposal. Failure retry reopens only the failed track while healthy generations remain reusable.

Pause stops scheduled nodes and window pulls, retaining only the current bounded window for resume. Seek, playback-rate changes, and routing rebuilds stop obsolete sources and invalidate decoder generations. A pending play cannot override a later pause, seek, or teardown. Buffering an established engine retains audio clock authority; it cannot start an independent native-video clock. Selection looping clips sources at the Selection end and seeks through the existing transport command, with the accepted 100 ms control-plane wrap budget distinct from steady-state continuity.

Explicit channel modes use graph routing. Auto-fix quiet side uses bounded per-chunk analysis (at most 200 ms) for Preview; export continues to classify the full Selection. The user approved this Preview approximation for #109 on 2026-09-07. Alternating left-only and right-only passages may be centered individually in Preview while the complete Selection remains stereo on export. Audio and Export review explain the difference; choosing an explicit mode gives consistent placement. No full-track background Preview analysis or waveform dependency is introduced. WaveSurfer renders independently generated worker-backed **Waveform lanes** and never gates Preview readiness or owns audio transport.

`wavesurfer-multitrack` is no longer used; `wavesurfer.js` remains only for visual waveform rendering.

This revises [ADR-0022](./0022-preview-level-metering-adapter.md): **Preview level meters** no longer depend on a separate decoded-sample simulation because the **Preview audio engine** provides per-track and combined graph taps.

Each per-track tap branches after channel handling, **Track volume**, and **Preview audio monitoring** gain. A separate branch observes the explicit monitored-output mix before global **Preview volume** and mute. Every branch uses a `ChannelSplitterNode` and one `AnalyserNode` per displayed channel; analyser outputs remain disconnected so metering cannot duplicate audible output. The UI adapter owns smoothing, clip hold, and pause/stop decay, while the engine reports silence whenever its graph is not playing.
